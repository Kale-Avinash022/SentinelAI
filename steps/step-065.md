## 1. What to build

**Goal:** Find saturation behavior and verify bounded degradation as concurrency rises.

- Run a controlled 10-to-100-user spike and a short soak.
- Pause/slow workers to measure queue age, outbox growth, and drain.
- Observe database pools, provider bulkheads, memory, errors, and backpressure.

**Deliverable:** a spike/soak/backlog benchmark with saturation analysis

## 2. Why this matters

Capacity is a curve with failure behavior, not one requests-per-second number; the brief explicitly asks what happens as traffic grows.

## 4. How to build it

- Use local-only load and step concurrency gradually with a fixed request mix.
- Record the point where latency/errors/queue age breach targets and which resource saturates first.
- Verify backpressure rejects before durable capacity is exceeded and recovery drains without duplicate effects.
- Keep soak duration realistic for the laptop and disclose it; do not claim long-term stability from a short run.
- Compare pool/batch settings one change at a time.

## 5. Workflow for today

1. Define spike/soak/backlog profiles and stop conditions.
2. Run the spike while collecting system and application metrics.
3. Repeat with workers paused, then resume and measure drain.
4. Inspect connection pool/bulkhead/backpressure behavior.
5. Save raw curves and an interpretation with limits.

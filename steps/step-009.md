## 1. What to build

**Goal:** Turn the reviewed models into a constrained schema with explicit application-role privileges.

- Generate and inspect migrations for the Week 2 domain tables.
- Add foreign keys, uniqueness rules, and common tenant/time indexes.
- Grant only required DML to sentinel_app and keep DDL with the migration role.

**Deliverable:** an applied, inspected tenant schema with least-privilege grants

## 2. Why this matters

The database should reject impossible data even when application code has a bug, and the app role should not be able to weaken its own controls.

## 4. How to build it

- Use UUID primary keys, TIMESTAMPTZ timestamps, and NUMERIC for money.
- Add unique constraints such as organization email and application/environment/name where the product requires them.
- Inspect autogenerated migrations for dropped/recreated constraints and correct them before applying.
- Grant SELECT/INSERT/UPDATE only where needed; audit restrictions are added with the audit table.
- Document expand/contract migration discipline for later deployments.

## 5. Workflow for today

1. Generate a candidate migration from reviewed metadata.
2. Read the upgrade and downgrade SQL line by line.
3. Apply to an isolated test database, then local development.
4. Inspect indexes/grants through SQL and run constraint tests.
5. Add the migration to the normal integration gate.
